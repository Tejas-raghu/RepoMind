## Day 9.5 unified RAG flow — verified implementation

## Week 2, Day 13 — indexed code explorer (implementation verified; UI review pending)

- Inspection found that `repository_chunks` stores path, original line range, chunk ID, repository ID, and normalized chunk text, but no complete original file. `CodeChunker` uses 60-line windows every 50 lines. Oversized windows can split mid-line; HTML lines over 8,192 characters are blanked before storage. The explorer therefore reports `indexed_coverage` with `complete: false`, never a reconstructed full original file.
- Added repository-scoped `GET /api/repositories/{repositoryId}/files` and `/files/content?path=...`. The latter deduplicates matching overlap by original line number, marks missing or ambiguous lines as gaps, and marks conflicting overlap without choosing a version. It rejects invalid paths, missing repositories/files, and oversized views. The API reads only stored PostgreSQL chunks, never server filesystem paths.
- Added a nested Vue file tree, an indexed code viewer with original line numbers, gap/conflict labels, copy actions, lazy Shiki grammars for TypeScript, JavaScript, Vue, C#, JSON, and Markdown, and escaped plain-text fallback. Answer source cards can open their trusted path and cited range in the explorer. Repository changes cancel and clear earlier file requests.
